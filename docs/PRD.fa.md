# سند نیازمندی‌های محصول (PRD) — اطلس جهان‌نما

**نام محصول:** اطلس جهان‌نما / Global Atlas Engine  
**پلتفرم:** Android و Backend مبتنی بر Java/Spring Boot  
**مخاطب:** عموم کاربران، دانش‌آموزان، دانشجویان و پژوهشگران  
**زبان‌ها:** فارسی (fa) و انگلیسی (en)  
**نسخه سند:** 1.1  
**تاریخ وضعیت:** 2026-10-18

> **قانون وضعیت:** تیک‌خورده یعنی فایل، کد اولیه یا پیکربندی مربوطه در مخزن وجود دارد؛ به‌معنی Build موفق، تست عبوری، انتشار، پوشش کامل داده‌ها یا پذیرش نهایی نیست. هر قابلیت تا زمانی که معیار پذیرش آن با داده واقعی و تست مناسب اثبات نشده باشد، «کامل» محسوب نمی‌شود.

## 1. چشم‌انداز محصول

ساخت اطلس تعاملی جهان برای مشاهده کشورها و تقسیمات اداری سطح اول آن‌ها (ADM1)، با امکان انتخاب روی نقشه، جست‌وجوی فارسی و انگلیسی، مشاهده اطلاعات و منبع داده، و دسترسی آفلاین محدود.

### اهداف
- نمایش مرز کشورهای جهان تا جایی که داده مجاز و معتبر موجود باشد.
- انتخاب کشور و سپس انتخاب استان/منطقه اداری سطح اول روی نقشه.
- ارائه صفحه اطلاعات کشور و منطقه.
- جست‌وجوی کشورها و مناطق با نام‌های فارسی و انگلیسی.
- نگهداری یا دانلود اطلاعات و هندسه منتخب برای استفاده آفلاین.
- نمایش منبع، مجوز، نسخه و تاریخ مرجع داده‌های جغرافیایی.
- حفظ معماری ماژولار، قابل تست و قابل نگهداری.
- ساخت و بررسی خودکار کد اندروید و بک‌اند از طریق CI.

### خارج از محدوده MVP
- مسیریابی خیابانی و راهنمای turn-by-turn.
- تضمین نام‌گذاری یکسان برای تقسیمات همه کشورها.
- ادعای پوشش کامل برای کشورهایی که داده معتبر ADM1 ندارند.
- حساب کاربری اجباری، پرداخت یا شبکه اجتماعی.

## 2. کاربران و سفرهای اصلی

- **کاوشگر:** نقشه را باز می‌کند، کشور را انتخاب می‌کند و به مناطق اداری آن می‌رود.
- **دانشجو/پژوهشگر:** نام و اطلاعات کشور یا منطقه را جست‌وجو و منبع داده را بررسی می‌کند.
- **کاربر آفلاین:** هنگام اتصال داده منتخب را دریافت کرده و بعداً بدون اینترنت مشاهده می‌کند.

### معیارهای پذیرش سفر اصلی
- [ ] انتخاب کشور از روی نقشه، نام صحیح و کد ISO را نمایش می‌دهد.
- [ ] پس از انتخاب کشور، همه هندسه‌های ADM1 موجود در دیتاست واردشده نمایش داده می‌شوند.
- [ ] انتخاب منطقه، جزئیات همان منطقه و پیام مناسب برای اطلاعات ناقص را نشان می‌دهد.
- [ ] جست‌وجو در فارسی و انگلیسی با حالت‌های loading، empty و error کار می‌کند.
- [ ] اطلاعات و هندسه دانلودشده بدون اینترنت قابل مشاهده‌اند.
- [ ] منبع، مجوز، نسخه و تاریخ مرجع در صورت موجود بودن قابل مشاهده است.
- [ ] سفر کامل روی شبیه‌ساز و دستگاه واقعی تست شده است.

## 4. معماری فنی

### اندروید
- Kotlin، Jetpack Compose، MVI و Clean Architecture.
- Hilt برای Dependency Injection.
- Gradle Kotlin DSL و ساختار app/core/feature.
- Retrofit برای شبکه و MapLibre برای نقشه.
- Room و DataStore برای دسترسی آفلاین برنامه‌ریزی شده‌اند.
- Coroutines/Flow و UI state تغییرناپذیر.

**ماژول‌ها:** `:app`، `:core:common`، `:core:model`، `:core:designsystem`، `:core:network`، `:core:database`، `:core:datastore`، `:core:map`، `:core:testing`، `:feature:atlas`، `:feature:country`، `:feature:region`، `:feature:search`، `:feature:downloads`.

**قواعد وابستگی:** Featureها می‌توانند به Core وابسته باشند؛ Core نباید به Feature یا App وابسته شود. قراردادهای Domain نباید به UI اندروید یا DTOهای انتقال شبکه وابسته باشند. ماژول App محل ترکیب وابستگی‌ها و Navigation سطح بالا است.

### بک‌اند
- Java 21 و Spring Boot 3.x با constructor injection.
- REST/GeoJSON، PostgreSQL + PostGIS و Flyway.
- API کشورها، مناطق، هندسه نقشه و در آینده متادیتای دیتاست.
- ورود داده نسخه‌دار همراه با اعتبارسنجی و attribution.

## 8. نیازمندی‌های غیرعملکردی

- **کارایی:** اندازه‌گیری cold start، زمان آماده‌شدن نقشه، تأخیر انتخاب، زمان پاسخ جست‌وجو، حافظه و حجم دانلود.
- **پایداری:** مدیریت قطعی شبکه، خطای HTTP، داده غایب، هندسه نامعتبر و دانلود نیمه‌کاره.
- **امنیت:** HTTPS در نسخه release، عدم ذخیره secret تولیدی در کد، اعتبارسنجی ورودی و اسکن وابستگی‌ها.
- **دسترس‌پذیری:** RTL/LTR، TalkBack، فونت مقیاس‌پذیر و کنتراست مناسب.
- **حریم خصوصی:** عدم نیاز به حساب یا رهگیری در MVP؛ اعلام شفاف analytics در صورت اضافه‌شدن.
- **کیفیت داده:** نسخه دیتاست قابل ممیزی، گزارش پوشش، هندسه معتبر و attribution.
- **نگهداشت‌پذیری:** مرز ماژول‌ها، تست قرارداد، تست واحد/یکپارچه/UI و CI.
- **حقوقی:** رعایت مجوز geoBoundaries و سیاست استفاده و attribution سرویس tile.

## 11. ریسک‌ها و راهکارها

1. **شکاف داده ADM1 یا مرز مورد اختلاف:** پوشش را برای هر ISO و منبع ثبت کن؛ مرز یا داده‌ای را جعل نکن.
2. **حجم بالای GeoJSON:** ساده‌سازی هندسه، query محدود به محدوده/سطح زوم و cache.
3. **ناسازگاری نسخه‌ها:** ترکیب Gradle/AGP/Kotlin/KSP/Hilt/MapLibre/SDK در CI اعتبارسنجی شود.
4. **فضای آفلاین:** دانلود انتخابی، محدودیت حجم، checksum و حذف داده قدیمی.
5. **کمبود ترجمه:** fallback نام و گزارش کامل‌بودن ترجمه.
6. **محدودیت tile server:** attribution آشکار و سرویس مجاز.
7. **امنیت:** حذف تنظیمات cleartext permissive از نسخه production.

## 12. تعریف تکمیل (Definition of Done)

یک قابلیت فقط زمانی کاملاً انجام‌شده است که:
- پیاده‌سازی و مرز ماژول‌ها بازبینی شده باشند؛
- تست‌های مناسب واحد/یکپارچه/UI موفق باشند؛
- Build اندروید/بک‌اند و CI موفق باشند؛
- حالت‌های خطا، خالی و آفلاین مدیریت شده باشند؛
- دسترس‌پذیری و بومی‌سازی بازبینی شده باشند؛
- منبع، مجوز و provenance داده مستند باشند؛
- معیار پذیرش با داده واقعی اثبات شده باشد.
